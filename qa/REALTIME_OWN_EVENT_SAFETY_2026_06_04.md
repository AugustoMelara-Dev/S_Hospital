# Realtime own-event safety - 2026-06-04

Decision: `PASS`.

Scope:

- Reduce repeated operator notifications in multi-PC LAN cashier workflows.
- Keep query invalidation for every broadcast event so the local screen stays fresh.
- Suppress only the toast generated by the same authenticated actor.

Observed result:

- Backend broadcast payloads for invoices, payments and cash sessions now include
  `actor_id`.
- Frontend session state keeps the active user id in a small runtime cache.
- `useBroadcastSync` checks the current user at event time, not only when the
  subscription starts, so login/logout changes do not leave stale notification
  behavior.
- Legacy events without `actor_id` still notify the user instead of silently
  hiding remote changes.
