Servidor Local LAN - Offline

Guía de operaciones, caja, recibos, respaldos y recuperación del Sistema de Caja Hospitalaria

1. Introducción y Accesos Rápidos (Shortcuts)

El sistema S_Hospital está optimizado para agilizar el registro y cobro de transacciones en la clínica u hospital sin depender de una conexión a internet. La pantalla de facturación permite al cajero registrar servicios rápidamente con el teclado.

Atajos de Teclado del Punto de Venta (POS)

Atajo Acción en Pantalla Detalle Técnico
F2 Cobrar / Pagar Abre el modal de cobro directo para seleccionar método de pago e ingresar el efectivo.
F4 Buscar Paciente Enfoca el campo del nombre del paciente para una captura ágil sin usar el mouse.
F8 Vaciar Carrito Limpia todos los servicios agregados de la venta activa.
Esc Cerrar Modales Cierra cualquier modal emergente en pantalla de manera instantánea.
Enter Confirmar Acepta selecciones o confirma transacciones en formularios activos.

2. Protocolos de Anulación de Facturas

Por motivos de transparencia, cumplimiento fiscal y auditorías administrativas internas, ninguna factura es borrada físicamente de la base de datos de S_Hospital.

Regla Fiscal
El correlativo fiscal otorgado en la secuencia activa debe mantenerse consecutivo. Si una factura se emite incorrectamente, se debe anular agregando una auditoría en lugar de eliminarla.

Procedimiento Operativo de Anulación:

  1. Un cajero identifica un error en una factura emitida y solicita la presencia del Supervisor o Administrador.
  2. El supervisor inicia sesión con su cuenta que dispone del permiso invoices.void.
  3. Ingresa al panel de Facturas y abre el detalle de la transacción correspondiente.
  4. Hace clic en Anular Factura.
  5. El sistema exige ingresar un motivo detallado de la anulación (mínimo de 10 caracteres). Ej: "Error de captura del servicio de Glucosa por parte del médico".
  6. Una vez confirmada, el estado cambia a void y el sistema registra de forma automática la anulación en el listado de auditoría operativa.

3. Apertura, Auditoría y Cierres de Caja

El control del flujo de dinero en efectivo y cobros digitales se administra de forma rigurosa por cada turno de cajero.

Ciclo de Caja Diario:

  • Apertura: Al iniciar el turno, el cajero debe aperturar la sesión ingresando el fondo de caja disponible en efectivo (ej. L. 500.00).
  • Registro: Todos los pagos de facturas emitidas por el cajero activo quedan estrictamente ligados a su sesión de caja.
  • Salidas y Entradas: Cualquier movimiento de efectivo ajeno a una factura (ej. pago menor a proveedor local) debe registrarse en el panel de caja.
  • Cierre y Arqueo: Al terminar el turno, el cajero cuenta físicamente el dinero, ingresa el monto total de cierre, y el sistema calcula la diferencia esperada.
Atención Auditores
Cualquier diferencia mayor a la tolerancia configurada por administración debe justificarse formalmente por el cajero y validarse por el supervisor a cargo antes de permitir un nuevo turno.

4. Respaldos (Backups) y Recuperación ante Desastres

El sistema S_Hospital almacena de forma 100% local todos sus datos. La seguridad de la información reside en un plan regular de respaldos.

Creación de Backups Manuales

Los administradores pueden generar y descargar copias de seguridad de la base de datos MariaDB directamente desde el panel administrativo web en el apartado de Copias de Seguridad.

Procedimiento de Restauración (Restore) en Servidor

Para restaurar la base de datos de S_Hospital ante un fallo catastrófico de disco, siga estos pasos:

Peligro de Pérdida de Datos
Nunca restaure directamente sobre la base activa del hospital sin prueba previa en una base descartable, respaldo final reciente y aprobación administrativa.

Paso A: Comprobación de Hash del Archivo

Verifique que el archivo SQL de respaldo no esté corrupto calculando su hash SHA256:

Get-FileHash C:\backups\hospital-backup.sql -Algorithm SHA256

Paso B: Restaurar en Entorno de Pruebas

1. Inicie sesión en MariaDB local y cree una base de datos limpia de pruebas:

CREATE DATABASE hospital_restore_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

2. Cargue el archivo SQL en la base de pruebas:

mysql -u root -p hospital_restore_test < C:\backups\hospital-backup.sql

3. Modifique temporalmente el archivo .env en el backend para apuntar a la base de pruebas y corra el test suite para validar la integridad de la base:

php artisan test

Paso C: Restaurar en Producción

Una vez verificado que el backup está íntegro y que el sistema arranca con normalidad en pruebas, aplique la restauración en producción deteniendo previamente los accesos LAN para evitar colisiones.

5. Operacion Local en Red del Hospital

El sistema debe usarse desde la computadora servidor y las computadoras autorizadas de la red local del hospital. Antes de iniciar una jornada real, confirme que el servidor responde, que la caja esta abierta por el cajero responsable y que los respaldos aparecen como protegidos.

Revision diaria recomendada

  • Abra el sistema desde una computadora cliente usando la direccion local indicada por administracion.
  • Ingrese con el usuario asignado; no comparta cuentas entre cajeros.
  • Verifique que la pantalla de respaldos muestre estado protegido o pendiente de revision.
  • Realice una impresion de prueba solo cuando administracion lo autorice.
Importante
No ejecute reinicios de base de datos, datos de practica ni herramientas de desarrollo en el servidor real del hospital. Si hay duda, detenga el flujo y contacte al responsable del sistema.

6. Soporte Técnico y Logs del Sistema

Ante cualquier eventualidad con la base de datos o fallos de transacciones en red local LAN:

  • Log de Laravel: Revise backend/storage/logs/laravel.log para obtener trazas detalladas de errores de PHP.
  • Servidor de Base de Datos: Puerto local estándar 3306 de MySQL/MariaDB.
  • Apertura de Firewall: Puerto de red LAN 8000.
