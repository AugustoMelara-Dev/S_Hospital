Manual de Usuario

Sistema de Caja Hospitalaria - operacion local en red del hospital

1. Abrir El Sistema

  1. Encienda la computadora servidor.
  2. Abra el acceso directo Abrir Sistema de Caja Hospitalaria.
  3. Desde una computadora cliente use la direccion LAN indicada por administracion.
  4. No use localhost desde una computadora cliente.
  5. Inicie sesion con su usuario asignado.
No comparta cuentas. Toda accion queda asociada al usuario que la ejecuta.

2. Caja Y Facturacion

  1. Abra caja con el efectivo inicial autorizado.
  2. Escriba el nombre del paciente.
  3. Busque y agregue servicios.
  4. Revise el total antes de emitir.
  5. Cobre una sola vez.
  6. Imprima el recibo.
Si el navegador se cierra o la PC se reinicia, revise Caja e Historial antes de repetir una factura o un cobro.

3. Recibos E Impresion

Si no imprime, revise papel, energia y conexion. No repita factura ni cobro; reimprima desde Historial cuando el supervisor lo autorice.

4. Anulaciones Y Reimpresiones

Las facturas no se borran de la base de datos. Una anulacion requiere permiso, motivo y auditoria. Una reimpresion debe registrar motivo si el sistema lo solicita.

5. Cierre De Caja

  1. Revise pagos por metodo.
  2. Cuente efectivo real.
  3. Ingrese monto contado.
  4. Registre diferencia y nota si aplica.
  5. Confirme cierre con supervision cuando sea necesario.

6. Respaldos

El administrador debe revisar que Respaldos muestre Todo bien, Requiere revision o Error. Un respaldo manual debe pasar de Pendiente a Protegido.

No restaure una base real sin probar primero en una base descartable y sin autorizacion.

7. Si Algo Falla

  1. Abra Ayuda dentro del sistema.
  2. Presione Preparar resumen.
  3. Entregue ese resumen al supervisor o responsable de soporte.

Si el sistema no abre, use la reparacion segura:

powershell.exe -ExecutionPolicy Bypass -File scripts\repair_hospital_system.ps1 -BaseUrl http://127.0.0.1:8000

Si soporte necesita mas evidencia, genere un paquete seguro:

powershell.exe -ExecutionPolicy Bypass -File scripts\collect_support_packet.ps1 -RunRepairDiagnostic -SkipDockerStart
No envie .env, respaldos SQL, passwords, tokens ni logs completos por canales no autorizados.

8. Capacitacion Segura

No practique anulaciones, restauraciones, cobros ficticios ni pruebas de base de datos en produccion. Si no existe modo practica aislado, use una instalacion separada o una base descartable autorizada.

9. Acciones Prohibidas En Produccion

  • Ejecutar migrate:fresh.
  • Ejecutar seeders de prueba.
  • Borrar facturas, pagos o carpetas de datos.
  • Borrar volumenes de base de datos.
  • Usar cuentas compartidas.
  • Repetir facturas o cobros para probar si algo fallo.
  • Restaurar backups sobre la base real sin autorizacion y prueba previa.

10. Cierre De Incidente

  1. Abra el sistema.
  2. Inicie sesion.
  3. Revise caja e historial.
  4. Revise respaldos.
  5. Anote que accion resolvio el problema.
