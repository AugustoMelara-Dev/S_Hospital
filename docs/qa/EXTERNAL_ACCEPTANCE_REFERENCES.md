This file records official external references used to prepare the field acceptance package. It is not a production go-live approval. Physical LAN, printer, restore and load gates remain pending until executed with real hospital equipment and synthetic data.

## References

| Topic | Official source | Applicable conclusion | Decision for S_Hospital | Risk | Requires physical operator |
| --- | --- | --- | --- | --- | --- |
| Docker Desktop networking on Windows | [Docker Desktop networking](https://docs.docker.com/desktop/features/networking/) | Published services can be reached through host ports; LAN reachability depends on host networking and firewall configuration. | The hospital server must expose only the intended local HTTP port to the private LAN. | A wrong bind/firewall rule can either block clients or expose the service too broadly. | Yes |
| Docker Compose service networking | [Docker Compose networking](https://docs.docker.com/compose/how-tos/networking/) | Compose creates an application network and service names can resolve inside that network. | Keep backend, frontend/proxy and MariaDB deployment isolated inside the local stack; expose only the browser entry point. | Misconfigured ports can bypass intended isolation. | Yes |
| Docker port publishing | [Docker Engine port publishing](https://docs.docker.com/engine/network/port-publishing/) | Published ports are reachable on host interfaces according to bind address and firewall rules. | Bind deployment ports deliberately and document the LAN URL used by client PCs. | Publishing to all interfaces may expose the app outside the expected network. | Yes |
| Windows Firewall overview | [Microsoft Learn - Windows Firewall](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/) | Windows Firewall filters traffic by profile, rule, app and port. | Operator must verify a private-network inbound rule for the S_Hospital port only. | Firewall may block second PC access or allow unintended networks. | Yes |
| Windows Firewall rules | [Microsoft Learn - Firewall rules](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules) | Rules should be scoped to needed profiles, addresses and ports. | Field guide requires documenting port, profile, responsible person and time if a rule is changed. | Broad rules can weaken LAN security. | Yes |
| Windows Firewall command line | [Microsoft Learn - Configure with command line](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line) | PowerShell can create firewall rules, but changes affect the machine firewall. | This package provides check guidance; it does not automatically change firewall state. | Automatic firewall changes without operator approval are unsafe. | Yes |
| Microsoft Edge printing | [Microsoft Support - Print in Microsoft Edge](https://support.microsoft.com/en-us/edge/print-in-microsoft-edge) | Browser print preview controls printer, pages, orientation, scaling and paper size. | Operator must confirm 100%/actual size, no unwanted browser headers/footers, and the selected printer/paper. | Browser scaling can produce clipped receipts even if the PDF is correct. | Yes |

| Epson Windows print settings | [Epson Windows basic settings](https://files.support.epson.com/docid/cpd5/cpd57990/index.html?page=source%2Fprinters%2Fsource%2Fprinting_software%2Fwindows_fy13%2Ftasks%2Fselecting_basic_windows_fy14.html) | Document size, orientation and paper source are selected in the driver. | The field log records driver settings per format. | Wrong driver settings can invalidate physical print evidence. | Yes |
| Epson custom paper settings | [Epson more Windows settings](https://files.support.epson.com/docid/cpd5/cpd57990/index.html?page=source%2Fprinters%2Fsource%2Fprinting_software%2Fwindows_fy13%2Ftasks%2Fselecting_more_windows_bus_fy14.html) | User-defined paper sizes may be configured in the driver. | Custom half-page profiles must be measured and tested, not assumed. | Custom paper may work on one PC and fail on another. | Yes |
| Laravel deployment | [Laravel deployment documentation](https://laravel.com/docs/13.x/deployment) | Production deployments should cache configuration/routes/views where appropriate and clear stale optimized cache when needed. | Deployment checklist must verify env/cache state on the local server before field acceptance. | Stale config can point to wrong DB, URL or cache. | No |
| Laravel configuration cache | [Laravel configuration documentation](https://laravel.com/docs/13.x/configuration) | `config:cache` and optimize commands affect runtime configuration. | Any server configuration change must be followed by the documented cache refresh process. | Hidden stale config can create hard-to-diagnose LAN failures. | No |
| Playwright CLI | [Playwright test CLI](https://playwright.dev/docs/test-cli) | `npx playwright test` executes selected specs and supports config selection. | Digital browser evidence uses the repository Playwright scripts, not ad-hoc manual clicking as the only proof. | Wrong base URL may test another local app. | No |
| Playwright running tests | [Playwright running tests](https://playwright.dev/docs/running-tests) | Playwright can run tests headless and collect traces/screenshots depending on configuration. | Logs and screenshots are stored under `qa/field-acceptance/` when produced. | Screenshots with mocked API do not replace real LAN acceptance. | No |

| MariaDB restore guide | [MariaDB restore guide](https://mariadb.com/docs/server/mariadb-quickstart-guides/mariadb-restore-guide) | Restores should target the intended database and be verified after import. | Never restore over a production database during acceptance. | Wrong target database can destroy real data. | Yes |

| MySQL mysqldump | [MySQL `mysqldump`](https://dev.mysql.com/doc/en/mysqldump.html) | `mysqldump` generates SQL statements that can recreate schema/data. | MySQL-compatible installations can use logical dump/restore with the same disposable-restore rule. | Version differences can affect restore behavior. | Yes |
| MySQL backup and recovery | [MySQL backup and recovery](https://dev.mysql.com/doc/refman/8.0/en/backup-and-recovery.html) | Backup and recovery procedures are essential operational controls. | Field acceptance cannot approve production without a verified restore path. | No restore proof means unacceptable recovery risk. | Yes |

## Operating decision

The official references support the same acceptance rule already used by S_Hospital: digital validation can be PASS, but physical production remains NO until the hospital executes and signs the LAN, printer, disposable restore and real load gates.
